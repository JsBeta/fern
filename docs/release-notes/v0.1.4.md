## 本次更新

### 新增：上传前检查剩余空间

- `PUT/POST /_api/upload` 在读取第一个分片、创建 `<name>.fernpart` **之前**，先比对目标所在卷的可用空间与「这个文件还差多少字节」。装不下就直接返回 `507 {"error":"no_space"}`，一个字节都不写。
- 判断依据是整个文件的剩余量（`total - offset`），不是单个分片，所以超大文件在开始传输时就会被拒绝，不会传到最后几 MB 才失败。
- 续传时按剩余字节计算，已落盘的 `<name>.fernpart` 不再重复计入需求；带 `restart=1` 重启时，即将被截断的那部分会算回可用空间。
- 目标子目录尚不存在（上传文件夹时常见）会向上找到最近的已存在祖先目录再测量，不会因为路径还没创建而跳过检查。
- `total` 未提供（长度未知）时退化为按当前分片长度估算，属于尽力而为的检查。
- 复用已有的卷空间缓存（5 秒 TTL），检查本身不引入额外的系统调用开销。

### 优化：磁盘写满不再报「写入失败」

- 写入途中真的写满（`ENOSPC`，以及配额相关的 `EDQUOT`）不再混进 `500 io_error`，而是映射为 `FsError::NoSpace` → `507 Insufficient Storage`，响应体 `{"error":"no_space"}`。
- 前端把该错误码翻译成「服务器磁盘空间不足」，不再显示含糊的「服务器写入失败」。
- 此前空间不足时界面会卡很久：写入失败后服务端仍要把剩余请求体读完（避免 TCP RST 让浏览器只看到 `Failed to fetch`），客户端还会自动重试三次，每次都是满载写盘；现在第一种情况在第一个字节前就被拦下，第二种情况至少能立刻看到准确的提示。

### 优化：Release 正文改由仓库维护

- 发布工作流改为读取 `docs/release-notes/<tag>.md` 作为 Release 正文；文件缺失时退回 GitHub 自动生成的 changelog。
- Release 已存在（重跑或手动触发）时用 `gh release edit --notes-file` 覆盖正文再上传产物，不必再事后用 API 补写说明。
- 因此本文件的正文与 `v0.1.4` 标签一起入库，发布完成后正文即已就位。

### 升级说明

直接替换可执行文件即可，配置文件与数据目录结构没有变化。行为上唯一可见的差异是：空间不足时上传会立即收到 `507 no_space`，而不是等很久之后收到 `500 io_error`；如果有脚本按 `500`/`io_error` 判断磁盘满，需要改为识别 `507`/`no_space`。

### 校验

下载后可用附件中的 `SHA256SUMS` 校验文件完整性：

```sh
sha256sum -c SHA256SUMS
```
