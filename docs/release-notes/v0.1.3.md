## 本次更新

### 新增：按分区的回收站

- 回收站不再固定为 `<root>/.Trash`，而是**跟着数据所在的卷走**：共享目录本身保留一份 `<root>/.Trash`，凡是被挂载到共享目录内部的分区（例如共享 `/mnt`，而 `/mnt/hdd1`、`/mnt/hdd2` 各自是独立挂载点）各有一份 `<挂载点>/.Trash`。
- 删除 `<root>/hdd1/a.txt` 时文件直接落到 `/mnt/hdd1/.Trash`，用一次 `rename` 完成，不再跨文件系统。此前所有条目都往 `<root>/.Trash` 塞，`rename` 跨设备会返回 `EXDEV`，删除直接变成 HTTP 500。
- 万一两端确实跨了设备（例如挂载点被临时改成 bind mount），会自动退化为「复制 + 删除」，操作仍然成功。
- 已发现的挂载点记在 `<root>/.Trash/bins.json` 的 `volumes` 数组里（根相对路径），重启后不必遍历目录树就能找回这些分回收站；扫描时也会顺带发现共享目录第一层的 `<root>/<磁盘>/.Trash`。
- 分回收站里的条目 id 带位置前缀，形如 `hdd1~l4k2p0`（前缀是挂载点路径的转义，`/` → `~1`，`~` → `~~`），原样回传给 `/_api/trash/restore`、`/_api/trash/purge` 即可。根回收站的条目仍是裸 id，旧链接、旧书签照常可用。
- `GET /_api/trash` 汇总根目录与各挂载点的回收站，`total`、`bytes` 一并统计。

### 兼容与安全

- 旧版本遗留在 `<root>/.Trash` 的扁平条目（`.<base36>.<name>`）依然能列出、恢复、彻底删除；分回收站里若有同类条目，也会自动加上位置前缀后呈现。
- 回收站目录仍然不对普通浏览开放：`GET /_api/list?path=/.Trash` 返回 403，`GET /files/.Trash/...` 返回 404，根目录与各挂载点下的 `.Trash` 一视同仁；复制接口同样拒绝把回收站目录当作源。
- 清洁逻辑（按天数 / 同名份数 / 总容量淘汰）改为遍历所有分回收站，`Trash.MaxDays`、`Trash.MaxBytes`、`Trash.KeepSame` 仍然是**整个共享目录共用**的三条上限，与旧版本语义一致，迁移后不需要调整配置。

### 升级说明

直接替换可执行文件即可。配置文件、`Trash.*` 指令含义、`.Trash/<id>/{meta.json,data/}` 的条目布局都没有变化。已有的 `<root>/.Trash` 会被继续使用，不会重建，也不会丢条目。

### 校验

下载后可用附件中的 `SHA256SUMS` 校验文件完整性：

```sh
sha256sum -c SHA256SUMS
```
