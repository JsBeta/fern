## 本次更新

### 修复：挂载点不再被当成普通目录删除

- 删除或剪切一个挂载点（共享目录下挂载的硬盘/分区）时，接口直接返回 `409 {"error":"mount_point"}`，前端提示「该目录是或包含挂载的磁盘（挂载点），请先在服务器上执行 umount 卸载」。不会再出现 `Resource busy (os error 16)` 的 500，也不会再留下半成品 `.Trash` 或 `bins.json` 登记项。
- 挂载点检查发生在创建回收站目录、登记卷之前；`Trash.Enabled 0` 的永久删除路径、回收站的彻底删除/清空同样受保护。
- 删除一个**包含**挂载点的父目录也会被拒绝：避免 `remove_dir_all` 递归进入被挂载的卷，把盘内内容先删光再在挂载点上报错。
- 挂载点识别不再只比较 `st_dev`：Linux/Android 解析 `/proc/self/mountinfo`（覆盖 bind mount、btrfs subvolume、文件夹挂载，路径里的 `\040` 等转义会还原）；Windows 用 `GetVolumePathNameW` 判断卷根，并枚举卷挂载路径检查目录内是否含挂载点；macOS/BSD 退回 `st_dev` 比较。
- 复制（`/_api/copy`）不受影响，仍可把挂载点内容当作普通目录递归复制。

### 优化：复制粘贴的命名规则

- 粘贴到**同一目录**：文件保留扩展名并追加 `_副本`，例如 `conf.toml` → `conf_副本.toml`，再次粘贴 → `conf_副本 (2).toml`；目录同理 `sub_副本`、`sub_副本 (2)`。
- 粘贴到**其他目录**：直接使用原文件名；只有目标目录已经存在同名项时才追加 `_副本` 后缀，跨目录整理文件不再被批量改名。
- 是否属于「同一目录」通过规范化路径比较，经符号链接或不同写法进入源目录也能识别。

### 升级说明

直接替换可执行文件即可，配置文件与数据目录结构没有变化。旧版本删除挂载点失败时可能留下空的 `<挂载点>/.Trash` 以及 `.Trash/bins.json` 里的登记项，都不影响使用；确认 `.Trash` 为空后可以手动 `rmdir` 清理。

### 校验

下载后可用附件中的 `SHA256SUMS` 校验文件完整性：

```sh
sha256sum -c SHA256SUMS
```
